# AI-тренер

Реализация: `portal/routers/ai.py` (137 строк) + фронтенд
`static/split_analysis_dialog.js`. Единственный AI-эндпоинт портала:
`POST /api/split-analysis/chat`.

## Кто отвечает на вопросы — не Anthropic API, а Claude Code CLI

В коде нет ни одного прямого HTTP-вызова к `api.anthropic.com` и нет
Python-SDK `anthropic`. Вместо этого сервер запускает установленный в
систему **Claude Code CLI** (`claude`) как обычный subprocess:

```python
command = [
    config.CLAUDE_CLI_PATH,   # путь к бинарю claude
    "-p", prompt,             # весь промпт одной строкой, без system/user-ролей API
    "--output-format", "stream-json",
    "--verbose",
]
if allowed_dir:
    command.extend(["--add-dir", str(allowed_dir)])
```

(`run_claude_prompt`, `portal/routers/ai.py:105`). Ответ читается построчно
из `stdout` как JSON-события; текст собирается из блоков
`event["message"]["content"]` с `type == "text"` у событий `type ==
"assistant"`. Процесс ожидается с таймаутом 120 секунд
(`process.wait(timeout=120)`); если текста нет — в ответ уходит `stderr`
или заглушка «Тренер не вернул ответ.».

Практические следствия такого решения:

- **Модель и лимиты не выбираются кодом портала** — используется дефолт,
  настроенный для CLI в его собственной конфигурации/подписке
  (`ANTHROPIC_API_KEY` или файл авторизации CLI в `HOME/.claude`, см.
  `.env.production.example`). В коде нет параметра `model=...`.
  *Какая именно модель отвечает сейчас — требует проверки на самом
  деплое* (`claude --version` / `claude config get model` в контейнере).
- **Нет настоящей многоходовой сессии.** Каждый вопрос — отдельный,
  независимый запуск `claude -p ...`. История диалога не хранится в
  CLI-сессии (`--resume`/`--continue` не используются) — вместо этого
  весь предыдущий диалог (`messages`, максимум 12 сообщений по схеме
  `SplitChatRequest`, из них берутся последние 8 при сборке промпта)
  текстом вклеивается в новый промпт при каждом запросе.
- **Картинка не идёт в теле запроса как base64 к модели напрямую** — она
  сохраняется на диск сервера, а CLI получает доступ к папке через
  `--add-dir`, после чего сам решает прочитать файл (промпт явно просит
  «Обязательно открой это изображение»). Это переиспользует
  файловые/инструментальные возможности Claude Code, а не Vision-параметр
  Messages API.
- **Нет системного промпта отдельно от пользовательского** — весь текст
  (роль тренера, формат ответа, контекст, история, вопрос) это один `-p`
  аргумент.

## Что видит AI-тренер (вход)

1. **Скриншот сплита**, собранный в браузере (`snapshotDataUrl()` в
   `static/split_analysis_dialog.js`): SVG-сцена диалога разбора сплита
   (карта, синий трек GPS, красная стрелка с чёрной обводкой — направление
   сплита, кружки КП) клонируется, картинка карты инлайнится как data URL,
   всё рендерится на `<canvas>` 1280×820 и экспортируется в PNG. Именно
   этот PNG уходит на сервер как `image_data_url` (`data:image/png;base64,...`)
   и сохраняется в `UPLOAD_DIR/split-analysis/<uuid>.png`
   (`save_split_snapshot`, `portal/routers/ai.py:91`) — файлы не
   удаляются автоматически.
2. **JSON-параметры сплита** (`splitPayload()` в JS): `label`, `from`/`via`/`to`
   (метки КП), `absolute_seconds`, `split_seconds`, `course_distance_meters`,
   `pace_seconds_per_meter`, число точек трека на этапе, индексы начала/конца
   отрезка трека, и, если пользователь нарисовал альтернативный вариант пути
   в диалоге, — `alt_route_length_meters`.
3. **История диалога** — последние сообщения (`user`/`assistant`) текущей
   сессии в браузере.
4. **Новый вопрос пользователя** (свободный текст, до 2000 символов,
   `question` в `SplitChatRequest`).

## Промпт (дословно из `build_split_chat_prompt`, `portal/routers/ai.py:44`)

Ключевые инструкции модели:

- «Ты AI-тренер по спортивному ориентированию **для девочки 13 лет**.
  Говори по-русски, спокойно, коротко и поддерживающе. Не ругай.»
- Разбирать **только выбранный сплит**, не всю дистанцию.
- Если карта передана — анализировать выбор пути по изображению (здания,
  заборы, «зелёнка», дороги, открытые места, обходы, варианты).
- Формат ответа: 2–5 коротких предложений, без markdown-таблиц, один
  конкретный совет в конце.
- Если картинки нет — явная инструкция «не делай выводы о препятствиях и
  выборе пути по карте».

## Что возвращается (выход)

`{"answer": "<текст ответа>"}` — простая строка, без структурированных
полей, без указания уверенности/источников. Ошибки CLI (не найден бинарь,
исключение при запуске) превращаются в текст ответа с описанием ошибки,
а не в HTTP-код ошибки — эндпоинт всегда отвечает `200`.

## Что не сохраняется на сервере

История диалога и текст ответов **не пишутся в БД** — живут только в
памяти вкладки браузера (`chatHistory` в JS) до закрытия диалога. Единственный
персистентный след разбора сплита — сама PNG-картинка на диске и, отдельно,
причина ошибки, если пользователь сохранил её через опросник
(`split_error_reviews`, см. [`data-model.md`](./data-model.md)) — это
не связано с текстом ответа AI-тренера напрямую.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `CLAUDE_CLI_PATH` | путь к бинарю `claude`; dev-дефолт `/home/<user>/.local/bin/claude` (зависит от машины разработчика), в Docker-образе `/usr/local/bin/claude` (CLI ставится отдельным слоем в `Dockerfile` через `npm install -g @anthropic-ai/claude-code@latest`) |
| `ANTHROPIC_API_KEY` | опциональный способ авторизации CLI (пример в `.env.production.example`) |
| `HOME` | в продакшене переопределяется на `/data/orienteering`, чтобы CLI искал/хранил свои креды (`HOME/.claude`) на персистентном томе, а не в эфемерном контейнере |

В отличие от соседнего проекта `running-portal`, в этом репозитории
**нет отдельной страницы `/claude-auth`** для обновления OAuth-токена CLI
через браузер — как именно проводится первичный логин `claude` в
контейнере `orienteering`, в коде не описано. *Требует уточнения при
деплое/эксплуатации.*

# Интеграции

Портал не имеет собственного API соревнований — вместо этого он умеет
разбирать HTML/JSON/PDF, отдаваемые публичными сайтами протоколов, по
ссылке, которую вставляет пользователь. Вся логика — в
`portal/services/race_protocol.py` (сетевой запрос + разбор, 5 форматов)
и `portal/routers/race_results.py` (специфика Orgeo и sportident.online,
валидация URL).

## Точка входа импорта

`fetch_race_protocol(url)` (`race_protocol.py:22`) скачивает страницу через
`urllib.request.urlopen` (таймаут 20 с, `User-Agent: orienteering-portal/0.1`),
сама определяет кодировку: PDF по `Content-Type`/расширению → извлечение
текста через `pypdf`; иначе перебор `utf-8-sig` → charset заголовка →
`cp1251` (стандартная кодировка старых русских спортивных сайтов) → `utf-8`
с заменой ошибок как последний вариант.

`detect_protocol_format(content)` (`race_protocol.py:39`) выбирает один из
пяти парсеров по эвристикам формы, не по домену:

| Формат | Как определяется | Что это за источник (по наблюдениям в тестах/URL) |
| --- | --- | --- |
| `pdf_text` | текст содержит «ПРОТОКОЛ РЕЗУЛЬТАТОВ», «Фамилия, имя» и паттерн `N КП, X.XX км` | PDF-протокол, экспортированный из **SportOrg** |
| `sportident_online_html` | страница содержит `sportident.online`, `class='name_grup'`, `class='hoverRow'`, `../ol/split.php?id=` | **sportident.online** (только страница конкретной группы `?id=...&g=...`, см. валидацию ниже) |
| `js_score` | есть `const db = "...";`, а в блобе — колонки `Баллы`/`Итог` | рогейн/score-О протокол (тот же движок, что и `js_course`, судя по общему сигнатурному `const db`) |
| `js_course` | есть `const db = "...";`, без колонок score | протоколы на движке типа **o-site.spb.ru** (`_races/.../split.htm`) — классическая дистанция с фиксированными этапами |
| `legacy_html` | ничего из вышеперечисленного — таблица `<table class="rezult">` | более старый/простой HTML-формат протокола |

Дальше `kind` результата — `"course"` (фиксированные этапы КП, включая
эстафету с `lap`) или `"score"` (рогейн — набор КП без порядка, штраф за
опоздание) — прокидывается в `race_results.kind` и определяет, какой
код разбора сплитов используется на фронтенде и в дашборде
(`_prepare_race_result_view` vs `_prepare_score_result_view` в
`portal/routers/race_results.py`).

## Orgeo (`orgeo.ru`) — отдельный путь, не через `detect_protocol_format`

`_is_orgeo_url()` (по домену `*.orgeo.ru`) переключает импорт на выделенные
функции в `race_results.py`, потому что Orgeo отдаёт данные не HTML-таблицей,
а JSON:

- **Превью** (`_load_orgeo_preview_protocol`) — тянет `event/info/<id>`
  (HTML, для названия/описания события) и
  `event/export/event_id/<id>/sub_id/<sub_id>/format/json` (плоский экспорт
  результатов), парсит через `_parse_orgeo_export_groups`.
- **Финальный импорт конкретной группы** (`_load_orgeo_full_protocol`) —
  использует другой эндпоинт, `online/finish/<id>?s=<sub_id>&d=<группа>&api=json`
  (эффективно «живой» фид результатов), через `_parse_orgeo_live_groups`.
- URL для парсинга принимается в трёх видах (`_orgeo_event_context`):
  `event/export/event_id/<id>/sub_id/<sub_id>/format/json`,
  `event/info/<id>` (тогда `sub_id=1`), либо ссылка на «живое» табло
  `orgeo.ru/live/#/<id>/<sub_id>`.
- Отдельно есть код для многодневных стартов (последний коммит в истории —
  «Fix Orgeo multiday race import»).

## sportident.online — валидация перед импортом

`_validate_supported_import_url()` (`race_results.py:496`) требует, чтобы
ссылка была не просто на событие (`/ol_new`), а конкретно на группу со
сплитами — наличие query-параметра `g` (номер группы). Если его нет,
пользователю показывается понятная ошибка с примером правильного URL
(`?id=<event>&g=<group>`), а не «сырая» ошибка парсинга.

## Полу-универсальный HTML/PDF-парсер

Для всего остального (не Orgeo, не sportident.online) `_load_protocol()`
просто скачивает страницу и прогоняет через
`parse_race_protocol_html`/`detect_protocol_format` — то есть теоретически
подойдёт любой сайт, отдающий один из трёх «универсальных» форматов
(`js_course`/`js_score`/`legacy_html`), не только `o-site.spb.ru`, но в
явном виде под другие домены код не написан и не тестировался. Реальный
набор источников, с которых **фактически** импортируются протоколы —
*не задокументирован явно в коде и требует уточнения у владельца*; по
URL-ам в тестах и в `race_grabber.py` уверенно подтверждаются `o-site.spb.ru`,
`orgeo.ru`, `sportident.online`.

## Поиск стартов участника («граббер», `race_grabber.py`)

Отдельная фича `/race-results/grabber` — не импорт по известной ссылке, а
**обратный поиск**: по имени участника ищутся все его старты на
`o-site.spb.ru`, перебором:

1. Найти страницы календаря (`calendar.php`, постранично) и, при флаге
   `include_archive=True`, до `ARCHIVE_YEARS_LIMIT = 3` последних лет
   архива (`archive.php?year=...`).
2. С каждой страницы вытащить ссылки на события (`race.php?id=...`).
3. На странице события найти ссылки со словом «сплит»/«split» в тексте —
   это и есть страницы конкретных групп со сплитами.
4. Разобрать каждую такую страницу протокола и найти участника по
   регистронезависимому вхождению строки поиска в поле «имя».

Результат — список совпадений (`event_name`, `race_page_url`, `split_url`,
`group_name`, `participant_name`) плюс счётчики отсканированных
страниц/сплитов — используется UI, чтобы показать прогресс и дать
пользователю выбрать нужный старт для импорта одним кликом
(`_annotate_grabber_matches` в `race_results.py` помечает уже
импортированные совпадения).

Это может быть медленной операцией (последовательные сетевые запросы по
всем найденным страницам, без кэша и без ограничения параллелизма) —
`race_page_count`/`split_page_count` в ответе позволяют оценить объём
работы постфактум, но нет прогресс-индикатора по ходу выполнения на
сервере (запрос синхронный, отвечает только по завершении).

## GPX-трек

`portal/services/gpx.py` — минимальный самописный парсер поверх
`xml.etree.ElementTree` (без сторонней GPX-библиотеки типа `gpxpy`).
Понимает только точки `<trkpt lat=".." lon="..">` с опциональными
`<ele>`/`<time>` внутри, независимо от namespace (сравнение по локальному
имени тега). Бросает `ValueError`, если в файле нет ни одной точки трека.
Не разбирает маршрутные точки (`<wpt>`) или маршруты (`<rte>`) — только
треки (`<trk>/<trkseg>/<trkpt>`).

## Внешние сервисы, не относящиеся к протоколам

- **Claude Code CLI** — не «интеграция» в смысле HTTP API, а локальный
  процесс; подробности в [`ai-coach.md`](./ai-coach.md).
- **Chart.js** — подключается с CDN (`cdnjs.cloudflare.com`) прямо в
  шаблонах (`templates/index.html`, `templates/race_result.html` и др.),
  а не бандлится локально — единственная внешняя фронтенд-зависимость.
